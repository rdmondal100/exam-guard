# Accepted limitations

Known behaviours that were accepted on purpose or are not worth fixing in Stage 1, each tagged with its milestone. Reference only: read it when you touch the area, not at session start. Add a line when you accept a limitation.

- The grace period trusts the client's server-synced clock: a save can claim any `clientTs` up to the deadline and still be taken within the grace (M18).
- If the server is down past a student's deadline plus grace, the first watcher tick afterwards finalizes them at once; saves they could not send in that time are lost (M18).
- The session token is encrypted with the Windows user's DPAPI key, which protects against a copied file, not against the student themself; the token only gives the student their own exam (M17).
- A student can redefine `prompt` or remove the PSReadLine handler in the exam terminal: that line is still reported, later lines are then only in the transcript. Typing into the shell's own `[Console]` (for example `Read-Host`) appears only in the transcript (M15b). The terminal is an in-app channel that focus monitoring cannot see (requirements §11).
- The terminal switch is exam-wide; per-student toggles are Stage 2 (M15b). `terminal_closed` from a shell killed at app quit may not be sent before the app exits.
- Code runs have no memory or process limit (no Job Object since 2026-11-12): a program can use all the RAM or start many processes until Stop or the time limit. A JS out-of-memory run prints V8's long stack to stderr (not trimmed). C output uses CRLF.
- Run flags can reach gcc options such as `-wrapper` or `@file`; no wider than the terminal the student already has. A flag that stops before linking (`-c`, `-E`) ends as a failed run (M15c). JavaScript flags with `"` or `%` are refused, because cmd.exe hosts the run (2026-11-12).
- A program waiting on input for the 10 min wall time is killed as `time_limit` (M15c). The console is bound to the run panel: switching question or language remounts it and replays the last output; output of a run still going has no console to land in. A run started with a hidden console uses 80×24.
- `graphics.h` (WinBGIm) is not in the MSYS2 ucrt64 repo; students download it into `workspace\include|lib` (needs internet) and pass `-lbgi -lgdi32 -lcomdlg32 -luuid -loleaut32 -lole32` (M15c).
- pacman runs with `--noscriptlet` (packages that need install scripts may be incomplete), only `[ucrt64]` is configured, and `npm i -g` is not supported (local installs only) (M15a, M15d). `pip --target` puts everything in one folder: a second install at another version needs `--upgrade`, uninstall only works through `python -m pip`, and a package with no Windows wheel needs a compiler that is not wired in (M15d).
- Files panel: the 200 MB disk limit is checked only when the panel saves or creates, so a program can write past it and the panel then refuses saves; it reads the folder when shown and when a run ends (use Refresh for files made in the terminal); an edit made in the last 0.6 s before Run may be written after the program has read the old file; one `main.c` only (no multi-file builds), a relative `require('./x')` from `main.js` and ESM `import` from the workspace do not resolve (M15c, M15e).
- Teacher-provided files: locked once hosting starts (stop hosting, edit, host again); students who joined earlier get the new list at their next `welcome` and already-copied files are not replaced; they count toward the student's 200 MB quota; a file the antivirus blocks shows as a failed download; the download has a 20 s idle timeout per read and no overall limit (M15f).
- Autosave: while the link is down saves pile up in memory (cap 500, a later save of the same buffer supersedes the older); a failed `answer:save` IPC makes the renderer forget that buffer so the next tick resends it; a half-open socket is noticed only by the 15 s idle drop (M16).
- Every autosave is a full copy of the buffer (up to 128 K characters), so a long exam keeps many versions; 200 students × a save every 10 s of a 4 KB answer is about 80 KB/s into SQLite (M16).
- The transcript client cap (about 1 MB per app run) restarts from zero after an app restart; the server cap still applies (M17).
- A relaunch while the server is unreachable shows the lobby ("Connection lost. Trying again…"), not the exam, because the exam state is only known from the server; the work is safe in the queue (M17).
- `network_lost` needs the exam `running` and the student `active` or `locked`; a student who disconnects after submitting stays quiet (M17). "Leave this exam" is offered only while the link is `reconnecting` or `failed` (M17).
- The window stays locked while the exam is `running` and the student is working, as intended, if hosting stops or the teacher server dies. Windows shutdown/log-off fires `before-quit`, which is cancelled while locked; Windows may still force it (M13).
- `pnpm fetch-toolchains` must be run once per checkout (about 280 MB download, about 1 GB unpacked, gitignored) before Run works in `pnpm dev:student`. The Dev-C++ gcc 4.9 on some PCs does not support `-std=c++17`, so `EG_MINGW_DIR` must not point at it (M15).
- The monitor counts as inside: the app, the run's program, the compiler, the terminal's shell (by pid) and any program under the toolchains (by path). Since M59 the run folder no longer counts by path (a student could copy a browser into the workspace), so a GUI program the student built and started from the terminal, not with Run, counts as outside, like `notepad` started from there.
- Outside time (M22): the roster total grows only when the student comes back (`focus_returned`), so a stretch still in progress is not counted yet, and one that never ends (the exam ends first) is not counted at all. Alt-Tab, the Start menu and similar shell windows are foreground changes and show as short `focus_lost` / `focus_returned` pairs for `explorer.exe`; M31's classifier is where to filter them.
- Evidence (2026-11-12): kept in the app's memory (pictures) and offline queue (events, without pictures) until the server acks it; an app crash loses the pictures not yet sent, not the events. At most 500 unacked events in memory (the oldest go first).
- No relaunch and no tamper lock (removed 2026-11-12): a student who ends ExamGuard stops the monitoring; the teacher sees the socket close (`network_lost` after 10 s) and the student must start the app again to continue.
- The monitor is the app's own code, like the paste guard and the exam window: a modified app could skip it. There is no service a standard user cannot stop.
- Launches (2026-11-12): a program counts as launched when its first window appears (get-windows `openWindows`, every 2 s), so programs without a window (background tools, a script started with no window) are not reported, and one that opens and closes within 2 s is missed. Store apps hosted by `ApplicationFrameHost.exe` share one host process, so a second one is not a new launch. Windows' own shell hosts are skipped.
- Paste guard (M25): the remembered copies live in the renderer, so after an app restart (or a reload) text copied before it no longer pastes, and the clipboard is cleared again anyway. Pasting into other programs is not watched (the monitor reports switching to them). The guard is the app's own code, so a modified app could skip it. Dropped files are not checked; only dropped text is. Text copied from the exam into another program and copied back is allowed if unchanged.
- Screens and secure desktop (2026-11-12): Electron counts the screens that are part of the desktop, so a mirrored (duplicate) display counts as one. The lock screen is reported by `powerMonitor`; Ctrl+Alt+Del and a UAC prompt are inferred from "no window can be read for 2 s", so a long Alt-Tab hold could look the same, and they look alike (`secure_desktop {desktop:'secure'}`), without a screenshot. Task Manager started before the exam only shows in `processes_at_start`.
- Large insertion (M27): a typing tool that waits 25 ms or more between keys is not flagged (normal auto-repeat is about 33 ms); the exam terminal is not watched; Monaco edits at several places at once (rename, multi-cursor) and a long copy of text already in the editor count as the editor's own; within 500 ms of an allowed paste, a burst up to twice its size is not counted.
- Classification (M31): the short/long outside limits (10 s / 60 s) and the risk points are constants until Settings (M43); the risk score only grows; shots while away are timed on the student PC's clock; events stored before M31 keep their old severity and add no risk; exams created before M31 have an empty high-severity list unless the teacher fills it.
- Thumbnails (M29, M33): only the primary screen is captured (a second screen shows in the roster's screen count, not in the grid); a capture on the secure desktop gives no picture, so the tile keeps the last one and dims it after 15 s; a teacher socket more than 2 MB behind skips frames (all 200 on one page can skip a student's first frame, which then arrives one interval later); the grid's order can move a student to another page as the risk score changes.
- Teacher actions (M35): unshown messages are kept in server memory only (a server restart loses them; the audit log keeps the text), and the app acks a message when it arrives, so an app that crashes before the student closes the popup does not show it again. Extra time can only be added, not taken back. Locking and ending need a running exam; the confirmations are the browser's `confirm` dialog.
- Installer (M45–M46): unsigned (SmartScreen shows "Windows protected your PC": More info → Run anyway; lab IT can sign it or allow it by hash); the "delete data" uninstall choice reaches only the Windows user who runs the uninstaller (other users' `%APPDATA%\ExamGuard`, students' `%LOCALAPPDATA%\ExamGuard\run` workspaces stay); the firewall rules cover the Domain and Private profiles only.
- Load and hardening (M47, M49): the load numbers come from a plain Node server process on the dev PC with the sim on the same PC (no Electron, no real network); the laptop run is manual. Since M62 `event`, `transcript` and `readiness.report` are rate-limited per socket (burst 1000, so an offline replay fits); `answer.save` is not (the outbox keeps at most 500 and each is validated and batched), so a modified app could still flood saves. `minimatch` (ESLint, electron-builder) has a ReDoS advisory; it only runs at build time.

## In-app monitor (2026-11-12, replaces the Rust agent)
- Websites are read from Chrome and Edge only (UI Automation of the address bar, `SiteReader.exe`); Firefox, Brave, Opera and others give only their window title. A read takes about 120 ms and runs only when the window or its title changes; a page change that keeps the same title (digits aside) keeps the old site. The site is what the address bar shows, so a page the student is typing over keeps the last site.
- Private windows are recognised by the profile button's label in English, German, Spanish and Bengali wordings; another language shows a private window as a normal one with its address.
- Windows are polled (1 s for the front window, 2 s for launches), so a switch shorter than about a second can be missed. Outside time is counted from the tick that saw the switch.
- `SiteReader.exe` needs the .NET Framework 4 C# compiler to build (`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`, present on Windows 10/11); without it sites are not read and everything else works.
- ConPTY holds a program up to 3 s until the terminal answers its device-attributes query; the app's xterm.js answers at once, but the run time limit counts from the console's start (2026-11-12).
- Stop and the time limit use `taskkill /T /F` on the program's tree; a program that detached itself (`start`, `Start-Process`) survives Stop and the terminal's close.
- Pause (M58) freezes the exam screen only: a program already running and the monitor keep going, so a student who switches apps while paused is still logged. The terminal's "on for N minutes" window stands still and moves by the pause on resume (M60), but an open shell stays usable during the pause.

## Small follow-ups without an owner (moved from progress.md, 2026-11-03)
- tell the teacher which students' exam-file download failed (an app event in the hosting panel); show the exam from the first second after a relaunch by caching the last `SessionState` in the session file; copy/print/save for the receipt (the hash is shown in full); a "hosting stopped" screen for students whose socket drops because the teacher stopped hosting (they see "reconnecting" and retry); a "switch exam without an uninstall" path for a student whose link is `connected` to the wrong exam (Settings); `confirm` does not check that the exam is still hosting; the join rate limiter is in memory and keyed by the socket IP; `resume.lastServerSeq` stays 0 (M35 re-sends messages after each welcome instead); the teacher login screen does not show the "server restarted" banner after a restart; exams list and class-list students view are not paginated; class lists cannot be renamed or edited per student, and re-import into an existing list is not built; the question form has no markdown preview or "unsaved changes" prompt; the answer store is not cleared between exams in one app run (question ids are unique, so harmless); the server's WS `notice` message from protocol §3 is not built.
